Dopo questa versione l'utente può:

1. Aprire The Cleaner dall'Hub
2. Avviare l'analisi su tutti i track con `conforming_status = 'unknown'`

5. Selezionare i file da isolare e eseguire la quarantena in `_NonConform/`
6. Vedere il conteggio "Anomalies Detected" nell'Hub aggiornarsi automaticamente al prossimo scan

## Categorie di rilevamento

### 1. Pattern YouTube / video-rip (filename-based)

Analisi sul file stem (senza estensione), case-insensitive. Pattern applicati in ordine:

| Pattern regex | Esempio filename |
| --- | --- |
| `\(official\s+music\s+video\)` | `Artist - Title (Official Music Video).mp3` |
| `\[official\s+music\s+video\]` | `Artist - Title [Official Music Video].mp3` |
| `\(official\s+video\)` | `Artist - Title (Official Video).mp3` |
| `\[official\s+video\]` | `Artist - Title [Official Video].mp3` |
| `\(lyrics?\s+video\)` | `Artist - Title (Lyrics Video).mp3` |
| `\[lyrics?\s+video\]` | `Artist - Title [Lyrics Video].mp3` |
| `\(lyric\s+video\)` | `Artist - Title (Lyric Video).mp3` |
| `\[lyric\s+video\]` | `Artist - Title [Lyric Video].mp3` |
| `\(visuali[zs]er?\)` | `Artist - Title (Visualiser).mp3` |
| `\[visuali[zs]er?\]` | `Artist - Title [Visualizer].mp3` |
| `\(full\s+album\)` | `Artist - Album (Full Album).mp3` |
| `\[full\s+album\]` | `Artist - Album [Full Album].mp3` |
| `\(audio\)` | `Artist - Title (Audio).mp3` |
| `\[audio\]` | `Artist - Title [Audio].mp3` |
| `\(www\.[^)]+\)` | `Artist - Title (www.example.com).mp3` |
| `\[www\.[^\]]+\]` | `Artist - Title [www.example.com].mp3` |
| `[_\-][a-zA-Z0-9_\-]{11}$` | `Artist - Title_dQw4w9WgXcY.mp3` (YouTube ID) |

**Motivo della scelta**: L'analisi del nome file è la detection primaria perché non richiede apertura del file — è O(1) per file e non dipende da strumenti esterni. Copre il 90%+ dei video-rip scaricati da YouTube.

### 2. Video stream nascosto (FFprobe codec check)

Se FFmpeg è disponibile nel sistema (rilevato da `detect_ffmpeg_cmd`), viene eseguito:

```
ffprobe -v quiet -print_format json -show_streams -show_format <file>
```

Se l'output JSON contiene `"codec_type": "video"`, il file viene classificato come `video_stream`.

**Caso d'uso**: file `.mp4` rinominati in `.mp3`, o file `.mkv` rinominati in `.flac` — contenuto video mascherato da audio.

### 3. File corrotto (FFprobe failure o duration = 0)

Due condizioni:
- FFprobe non riesce ad aprire il file (exit code non-zero o spawn fallisce) → `corrupt`
- FFprobe apre il file ma `"duration"` è 0 o assente → `corrupt`

**Nota importante**: se FFprobe non è disponibile (FFmpeg non installato), le categorie 2 e 3 sono saltate completamente. Solo i pattern filename vengono applicati. Questo è documentato nell'UI con un avviso amber.

## Operazione di quarantena

### Non-distruttiva per design

Il modulo non elimina mai i file. L'operazione è `std::fs::rename` — spostamento, non copia+elimina.

### Cartella destinazione

```
<workspace_root>/_NonConform/<filename>
```

La cartella `_NonConform` viene creata automaticamente se non esiste.

### Gestione collisioni

La funzione `collision_safe_path` evita sovrascritture:
- Se `file.mp3` esiste già in `_NonConform`, il nuovo file viene rinominato `file_1.mp3`, `file_2.mp3`, ecc.
- Il loop continua finché trova un nome disponibile.

### Aggiornamento DB

Per ogni file spostato con successo:
```sql
UPDATE tracks SET path = '<nuovo_path>', conforming_status = 'non_conform' WHERE id = ?
```

Il path nel DB viene aggiornato al nuovo percorso in `_NonConform/` — le query future trovano ancora il file. Se l'utente sposta manualmente un file fuori dalla quarantena, la rescansione del workspace aggiornerà il DB.

#### Pipeline `detect_non_conform_impl`

1. Apre connessione DB read/write
2. Query `SELECT id, path, filename, file_size_bytes FROM tracks WHERE conforming_status = 'unknown'`
3. Compila i 17 pattern regex **una sola volta** (`build_patterns()`) fuori dal loop
4. Per ogni track:
   - Applica `check_youtube_pattern` → se match: `NonConformItem { reason: "youtube_pattern" }` + `continue`
   - Se FFprobe disponibile: esegue `probe_file` → categorizza `video_stream` o `corrupt`
   - Emette `"cleaner-progress"` ogni 50 file o all'ultimo
5. Emette evento finale `phase: "complete"`
6. Restituisce `CleanerResult` con lista completa

**Perché `continue` dopo youtube_pattern**: un file può avere sia il pattern YouTube che uno stream video (es. video rinominato). Ma la categoria `youtube_pattern` è sufficiente — evita di eseguire FFprobe inutilmente su file già classificati. Un file appartiene a una sola categoria.

**Parsing JSON FFprobe senza serde**: `extract_duration_from_json` usa ricerca stringa invece di deserializzare il JSON completo. Il JSON FFprobe è deterministico e strutturato — questa scelta evita dipendenze aggiuntive (`serde_json` già incluso ma le strutture FFprobe sarebbero verbose).

#### `quarantine_non_conform_impl`

1. Crea `_NonConform/` se non esiste
2. Per ogni `track_id`:
   - Query DB: recupera `path` e `filename`
   - Se il file non esiste più nel path originale → aggiorna solo DB (caso raro: file già spostato manualmente)
   - Calcola path destinazione collision-safe
   - `std::fs::rename` → aggiorna DB (nuovo path + `conforming_status = 'non_conform'`)
3. Restituisce `{ moved, failed }`

#### `deriveFfprobePath`

```typescript
function deriveFfprobePath(ffmpegPath: string | null): string | null {
  // Stessa directory di ffmpeg, nome "ffprobe" (o "ffprobe.exe" su Windows)
  // C:\...\ffmpeg.exe → C:\...\ffprobe.exe
  // /usr/bin/ffmpeg   → /usr/bin/ffprobe
}
```

Derivazione lato frontend — evita di aggiungere un comando Rust separato per trovare ffprobe.

## Flusso end-to-end v0.4.0

```text
Utente clicca "Start Analysis" in CleanerModule (Step 1)
  → setIsCleanerRunning(true)
  → invoke('detect_non_conform', { ffprobePath })

  [Backend Rust — thread spawn_blocking]
    SELECT tracks WHERE conforming_status = 'unknown'
    build_patterns() — compila 17 regex una sola volta
    Per ogni track:
      check_youtube_pattern(filename) → se match: NonConformItem { youtube_pattern } + continue
      probe_file(ffprobe, path) → ha video stream? → video_stream
                                → ffprobe fallisce? → corrupt
                                → duration = 0? → corrupt
      ogni 50 file: emit('cleaner-progress', { analyzed, total, current_file, found })
    emit('cleaner-progress', { phase: 'complete' })
    return CleanerResult { items: [...] }

  [Frontend — listener in App.tsx]
    ogni evento 'cleaner-progress' → setCleanerProgress() → CleanerModule aggiorna barra
    su phase='complete' → setIsCleanerRunning(false)

  invoke ritorna → setNonConformItems(result.items) → setStep(2)

Utente Step 2: seleziona file, clicca "Quarantine (N)" → Step 3
  → conferma → clicca "Execute Quarantine"
  → invoke('quarantine_non_conform', { workspacePath, trackIds })

  [Backend Rust]
    create_dir_all(_NonConform/)
    Per ogni track_id:
      collision_safe_path(dir, filename)
      std::fs::rename(src, dest)
      UPDATE tracks SET path=dest, conforming_status='non_conform'
    return QuarantineResult { moved, failed }

  → mostra risultato
  → utente clicca "New Analysis" → reset → Step 1
```

## Prossimo Step — v0.5.0: The Cleaner — Duplicate Detection

Con la detection non-conform completata, il prossimo step naturale è il rilevamento duplicati:

- Acoustic fingerprinting via `fpcalc` (AcoustID) — confronto tra tutti i track `conforming_status = 'ok'`
- Fuzzy matching: artista + titolo normalizzati (lowercase, strip accents)

- UI Step 2 "REVIEW": mostra coppie duplicate con match score, waveform comparativa statica, metadata delta

- Aggiornamento `conforming_status = 'duplicate'` nel DB
- Refresh stats Hub → counter "Duplicates Detected" si popola
