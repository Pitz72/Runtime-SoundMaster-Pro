# Changelog — v0.2.0 · Fase 2: Migrazione UI "Industrial" + Audit di Conformità Progetto

> **Data**: 2026-04-03
> **Autore**: Simone Pizzi — Runtime Radio
> **Tipo di release**: Sostituzione completa del design system + pulizia elementi UI non-progetto
> **Commit scope**: Redesign visivo totale basato sul prototipo Google AI Studio; rimozione/sostituzione di tutti gli elementi di interfaccia non previsti dallo spec; creazione del modulo Settings; bump di versione su tutti i manifest.

## Obiettivo di questa versione

Il design system v0.1.0 "The Brutalist Control Room" (verde radioattivo #39FF14) è stato giudicato non ottimale visivamente dall'autore dopo il confronto con un prototipo realizzato in Google AI Studio. La v0.2.0 sostituisce completamente l'estetica con il design system **"Industrial"** (ambra #FFB300 + ciano #A4E7FF su carbone scuro #131313) e porta ogni schermata a un livello di completezza visiva corrispondente al prototipo approvato.

In parallelo, l'obiettivo è garantire che **ogni elemento di UI sia giustificabile dallo spec di progetto**: elementi decorativi, placeholder fuori contesto e dipendenze da risorse esterne non pianificate sono stati rimossi o sostituiti. L'architettura Tauri/Rust/Zustand rimane intatta e integra.

### `src/components/modules/CleanerModule.tsx` — The Cleaner

**Riscrittura completa** da stub a UI funzionale (UI-only, logica backend Fase 3).

**Pipeline 3-step implementata:**

**Step 1 — SCAN**: schermata centrata con spinner animato (Framer Motion `rotate: 360` su `border-t-2`), bottone "Start Analysis" che avanza allo step 2 e logga l'evento.

**Step 2 — REVIEW**: layout `grid-cols-12` con:
- Colonna sinistra (4 col): lista conflict pairs con match score (%), tipo (ACOUSTIC/BINARY), bulk resolve buttons.
- Colonna destra (8 col): confronto waveform Source A / Source B (visualizzazione CSS con `Math.sin` deterministico — non casuale, riproducibile), metadata delta table.
- Mock data: 3 coppie di duplicati rappresentative dei casi reali (WAV/MP3, 98%/92%/100% match).

**Step 3 — RESOLVE**: schermata di risoluzione binaria (Keep A / Keep B) con ritorno allo step 1 dopo conferma.

Ogni transizione chiama `addLog` → store → LogPanel.

## Prossimo Step — v0.3.0 / Fase 3: The Cleaner Backend

Ora che la UI è stabile e allineata allo spec, il prossimo rilascio implementa la **logica Rust** di The Cleaner:
- Scansione ricorsiva del workspace (Rust `walkdir`).
- Calcolo hash SHA-256 binario per match esatto.
- Integrazione fpcalc per acoustic fingerprinting (Chromaprint).
- Confronto fingerprint con soglia di similarità configurabile.
- Quarantena file duplicati in cartella `_NonConform`.
- Esposizione comandi Tauri: `scan_library`, `get_duplicates`, `quarantine_file`.
- Collegamento UI CleanerModule con dati reali (sostituzione mock pairs).
