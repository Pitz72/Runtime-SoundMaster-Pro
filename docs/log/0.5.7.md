## Contesto

Prima di eseguire test reali su librerie di produzione, erano necessarie due funzionalità di supporto:

1. **File di log persistente**: capire esattamente cosa fa il software durante una sessione — quale file viene taggato come non-conforme e perché, quali duplicati vengono raggruppati, quanti file vengono spostati.
2. **Isolamento scansioni**: ogni nuova scansione dello stesso workspace deve ripartire da zero per i risultati di detection, senza ereditare stati da sessioni precedenti. Problema correlato: le cartelle `_NonConform` e `_Duplicates` venivano riscannerizzate e i file messi in quarantena venivano re-indicizzati come `'unknown'`.

Entrambe le funzionalità non richiedono nuove dipendenze Cargo.

## Feature 1 — File di log persistente (`logger.rs`)

### File creato

- `src-tauri/src/logger.rs` — modulo nuovo


## Feature 2 — Isolamento scansioni (`scanner.rs`)

### Problema

Il comportamento precedente:
1. La prima scansione indicizza i file con `conforming_status = 'unknown'`
2. Il cleaner li analizza e imposta `'non_conform'`, `'duplicate'`, ecc.
3. Una seconda scansione dello stesso workspace usa `INSERT OR IGNORE` — i file già presenti non vengono toccati
4. Il cleaner filtra solo `WHERE conforming_status = 'unknown'` → trova **0 file** da analizzare
5. **Risultato**: la seconda run sembra non fare nulla, i risultati precedenti restano in DB senza essere riverificati

### Fix: reset automatico all'avvio di ogni scansione

All'inizio di `scan_workspace_impl`, prima del Pass 1 (conteggio):

```rust
let reset_count = conn.execute(
    "UPDATE tracks SET conforming_status = 'unknown' WHERE path LIKE ?1",
    [format!("{}%", workspace_path)],
).unwrap_or(0);
```

Questo resetta `conforming_status = 'unknown'` per tutti i track il cui path inizia con il workspace — inclusi i file precedentemente spostati in `_NonConform` e `_Duplicates` (il cui path nel DB era stato aggiornato alla nuova posizione). Il conteggio viene loggato per visibilità.

**Effetto**: ogni nuova scansione produce una detection completamente fresh, come se fosse la prima volta. Il database conserva lo storico delle sessioni nella tabella `scans`, ma lo stato di ogni file viene sempre ricalcolato.

### Fix correlato: esclusione cartelle quarantena dal WalkDir

Prima del fix, il WalkDir attraversava anche `_NonConform/` e `_Duplicates/` (sottocartelle del workspace). I file quarantinati venivano re-indicizzati come nuovi track con `conforming_status = 'unknown'` — duplicando i record nel DB (path originale con status aggiornato + nuovo record con path nella quarantena).

Il filtro `is_audio_file` ora esclude le entry all'interno delle cartelle di quarantena:

```rust
const QUARANTINE_DIRS: &[&str] = &["_NonConform", "_Duplicates"];

// Nei due pass:
&& !entry.path().components().any(|c| {
    c.as_os_str().to_str()
        .map(|s| QUARANTINE_DIRS.contains(&s))
        .unwrap_or(false)
})
```

Il check percorre i componenti del path — se uno qualsiasi è `_NonConform` o `_Duplicates`, il file viene saltato.

### Conteggio file nuovi vs esistenti

Lo scanner ora distingue tra file nuovi (inseriti per la prima volta) e file già noti (aggiornati solo il `conforming_status`):

```rust
if let Ok(n) = stmt.execute(params![...]) {
    if n > 0 { new_files += 1; }
}
```

Il log finale riporta: `Completata: 36701 file totali, 0 nuovi, 32.4s` — `0 nuovi` indica una rescansione, un numero > 0 indica che sono stati aggiunti file alla libreria.
