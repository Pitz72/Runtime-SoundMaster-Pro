## 🎯 Obiettivo di questa versione

Construire The Hub: il nucleo della UI del progetto basato sul design system _The Brutalist Control Room_, mettendo in comunicazione il frontend React con il backend Rust Tauri già abbozzato nella **Fase 0**. In questo aggiornamento l'interfaccia passa dall'essere uno scaffolding mock a uno scheletro funzionale che ospiterà i tre moduli e gestirà il file system e i log in modo reattivo.

---

## ✅ Cosa è stato fatto

### 1. Architettura di Stato Globale (Zustand)

- **Pacchetti aggiunti**: `zustand`
- Implementato `src/store/appStore.ts` per far collassare tutte le dipendenze globali e mantenere i componenti puri (niente "prop-drilling").
  - `currentModule`: Stato router per passare tra (Hub / Cleaner / Conformer / Librarian).
  - `workspacePath`: Rappresentazione del percorso utente locale, fondamentale per procedere con le operazioni.
  - `systemStatus`: Specchio React dei tool Rust (`detect_ffmpeg`, `detect_fpcalc`, e controlli SQLite creati in Fase 0).
  - `logs`: Array di messaggi tracciati da tutte le parti dell'app per la console integrata (limitati alle ultime 200 iterazioni per non sporcare la RAM).

### 2. Layout Master Persistente & Console Live

- **`src/components/layout/MainLayout.tsx`**: Contenitore CSS Grid/Flexbox per un'applicazione desktop full-screen che blocca lo scrolling del body e isola il contenuto scrollabile.
- **`TopBar.tsx`**:
  - Breadcrumb dinamico del modulo (`Runtime SoundMaster Pro / The Cleaner`).
  - Stato di connessione al database e la validità dei moduli binari (spie semaforiche su SQLite, FFmpeg, fpcalc).
  - Gestione compatta del "Workspace Path" in testata.
  - Toggle switch per alzare e abbassare il LogPanel.
- **`LogPanel.tsx`**:
  - Console floating integrata al fondo dello schermo (`bottom-0`).
  - **Framer Motion** gestisce l'apertura e chiusura in stile Spring (`type: "spring"`), nascondendolo morbidamente sotto il layout.
  - Auto-scroll hardware-accelerato (`scrollIntoView` sui messaggi in ingresso attivi) con colorazione semantica su tre stati: verde (`success`), ambra (`warning`), rosso (`error`), neutro (`info`).

### 3. Navigazione Fluid-Route & Plugin Tauri Dialog

- Adattato `src/App.tsx` al pattern `AnimatePresence` mode="wait" di `framer-motion` come router senza path/hash per le single page app.
- Aggiunto `tauri-plugin-dialog` alle dipendenze Cargo.toml ed esposto in permissions JSON (capability `default.json`). Questo permette agli script di richiamare la dialog nativa del File System (Windows/Mac) isolando le path restrictions di sicurezza.
- Mappata la chiamata open all'interno della dashboard centrale `HubModule` per l'estrazione di absolute_paths.

### 4. Componenti Funzionali di Placeholder

Costruzione delle schermate intermedie `CleanerModule.tsx`, `ConformerModule.tsx`, e `LibrarianModule.tsx`. Ognuna implementa:
  - Header Brutalist System in continuità con la UI globale.
  - Indicatori visivi dello stadio di sviluppo corrente.
  - Animazioni di entrance/exit lineari gestite da React per mantenere alta la fluidità del Desktop App (zero drop-frames).

## 🔴 Modifiche in Corso d'Opera e Note Tecniche

- **Zustand come Bus di Sistema**: Ho strutturato l'accesso al logging non delegandolo ai singoli componenti (in App.tsx faceva un tracking caotico) ma incapsulando direttamente `invoke` e try-catch dentro action centralizzate di store oppure nell'avvio unico di App.tsx per evitare doppie chianate a Tauri al mount dei vari widget.
- **Framer-Motion per transizioni in Tauri**: Configurate animazioni da *200ms*, tempistica pensata per dare fluidità, ma allo stesso tempo una sensazione di reattività industriale, coerente con l'UI *control room*.
- **Bug fixing di Typescript**: Corretto un banale ma bloccante path resolution loop nel component intermedio `TopBar` che rompeva i flag `tsc`.
