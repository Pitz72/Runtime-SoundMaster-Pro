### 4. Modulo `src-tauri/src/db.rs` — SQLite con WAL Mode

Creato modulo completo per la gestione del database. Questa è la soluzione diretta alla criticità #1 e #2 documentate in `PIANIFICAZIONE.md`.

**Funzioni implementate:**
- `init_database(app_data_dir: &PathBuf) -> SqlResult<Connection>`: inizializza il DB con WAL mode
- `db_status(app: AppHandle) -> Result<String, String>`: comando Tauri per il frontend

**Schema SQL iniziale — tabelle create con `IF NOT EXISTS`:**

```sql
-- WAL mode obbligatoria (evita SQLITE_BUSY su scritture massive)
PRAGMA journal_mode=WAL;
PRAGMA cache_size=-64000;       -- 64MB cache
PRAGMA synchronous=NORMAL;

-- Tabella principale libreria
CREATE TABLE IF NOT EXISTS tracks (
    id, path, filename, artist, title, album,
    year, genre, bitrate, sample_rate, duration_secs,
    file_size_bytes, format, fingerprint, cover_hash,
    scan_id, conforming_status, created_at
);

-- Indici compositi per performance
CREATE INDEX IF NOT EXISTS idx_tracks_artist_title ON tracks (artist, title);
CREATE INDEX IF NOT EXISTS idx_tracks_status ON tracks (conforming_status);

-- Full-Text Search (per librerie 500k+ brani)
CREATE VIRTUAL TABLE IF NOT EXISTS tracks_fts USING fts5(
    artist, title, album, genre,
    content='tracks', content_rowid='id'
);

-- Sessioni di scansione
CREATE TABLE IF NOT EXISTS scans (...);

-- Cover art come BLOB separato dalla tabella principale
CREATE TABLE IF NOT EXISTS cover_art (...);
CREATE INDEX IF NOT EXISTS idx_cover_art_track ON cover_art (track_id);
```

**Lezioni da RAMP applicate:**
- WAL mode attivata fin dal primo `init()` — mai più `SQLITE_BUSY`
- Cover art in tabella separata — nessun gonfiore della tabella `tracks`
- FTS5 nativo — ricerche istantanee su database enormi senza librerie esterne

### 5. Modulo `src-tauri/src/ffmpeg.rs` — Auto-Detection FFmpeg

Implementata la funzione `detect_ffmpeg() -> FfmpegInfo` con 5 strategie di ricerca in ordine di priorità:

1. **Bundled** (`src-tauri/binaries/ffmpeg.exe`) — produzione, massima affidabilità
2. **PATH di sistema** — utenti con FFmpeg già installato
3. **Percorsi comuni Windows** — `C:\Program Files\ffmpeg\`, WinGet, ecc.
4. **Percorsi comuni macOS** — Homebrew (`/opt/homebrew/`, `/usr/local/`), MacPorts
5. **Percorsi comuni Linux** — `/usr/bin/`, `/usr/local/bin/`, Snap

**Probing**: ogni candidato viene verificato eseguendo `ffmpeg -version` e controllando l'exit code. Nessun path "finto" viene accettato.

**Struct risposta** (serializzata JSON per Tauri IPC):
```rust
pub struct FfmpegInfo {
    pub found: bool,
    pub path: Option<String>,    // path completo verificato
    pub version: Option<String>, // prima riga di `ffmpeg -version`
    pub source: Option<String>,  // "bundled" | "system_path" | "common_path"
}
```

## 🔴 Problemi Riscontrati e Risolti

### Problema 1: `create-tauri-app` crea sottocartella invece di inizializzare in-place
**Causa**: la CLI non supporta il pattern `npx create-tauri-app .` nella directory corrente in modo non-interattivo  
**Soluzione**: inizializzazione in sottocartella `Runtime-SoundMaster-Pro/`, poi migrazione con `Move-Item` PowerShell  

### Problema 2: `resource path binaries\ffmpeg-x86_64-pc-windows-msvc.exe doesn't exist`
**Causa**: Tauri 2.x valida l'esistenza degli `externalBin` anche durante `cargo check`/`cargo build --debug`  
**Soluzione**: creazione di file placeholder vuoti con il naming corretto Tauri (`binary-{triple}.exe`)  

### Problema 3: `no method named path found for AppHandle`
**Causa**: il trait `tauri::Manager` deve essere importato esplicitamente per usare `.path()` su `AppHandle`  
**Soluzione**: aggiunto `use tauri::Manager;` in `db.rs`
