## Bug e miglioramenti risolti

### FIX-1 — Workspace non selezionabile da The Cleaner

**Sintomo**: aprendo The Cleaner senza workspace, il bottone "Start Analysis" era disabilitato con testo "No Workspace Selected" ma non c'era nessun modo di selezionare la workspace da dentro il modulo.

**Fix**: aggiunto pannello di configurazione in cima allo Step 1 di entrambe le modalità (Non-Conform e Duplicates):

```
┌──────────────────────────────────────────────────────────┐
│ 📂 Source Workspace    /percorso/libreria         [Browse] │
│ 📥 Destination         /percorso/_NonConform      [Change] │
└──────────────────────────────────────────────────────────┘
```

- **Browse**: stesso dialog dell'Hub — seleziona la cartella e avvia automaticamente la scansione di indicizzazione (identico a `handleSelectWorkspace` dell'Hub)
- **Change**: permette di impostare una cartella destinazione custom per la quarantena, diversa dal default `_NonConform` / `_Duplicates` all'interno della workspace
- Le destinazioni mostrano sempre il path effettivo (default derivato da workspace, o custom se impostato)
- Il bottone "Start Analysis" / "Start Duplicate Scan" mostra testo contestuale: "Select a Workspace First" se non c'è workspace, "Scanning workspace..." durante lo scan

### FIX-2 — Messaggio FFmpeg non trovato più informativo

**Vecchio comportamento**: banner amber in primo piano con testo prominente "FFmpeg not detected — video stream checks skipped. Pattern matching only." — troppo invasivo, sembrava un errore bloccante.

**Nuovo comportamento**: box sottile con bordo amber/20, testo ridotto, posizionato dopo la descrizione principale. Rende chiaro che è un avviso non bloccante — il rilevamento YouTube patterns funziona sempre, FFmpeg è opzionale.

### FIX-3 — Destinazioni quarantena personalizzabili

**Nuovo parametro backend**: `quarantine_path: Option<String>` aggiunto a:
- `quarantine_non_conform(workspace_path, track_ids, quarantine_path)` in `cleaner.rs`
- `resolve_duplicates(workspace_path, resolutions, quarantine_path)` in `duplicates.rs`

Se `None`: usa il default `<workspace>/_NonConform` o `<workspace>/_Duplicates`.
Se `Some(path)`: usa il path specificato direttamente.

### FEATURE — FFmpeg/fpcalc Sidecar Bundling (Tauri v2)

**Problema**: `ffmpeg.rs` e `fpcalc.rs` cercavano il binario bundled con un path relativo (`PathBuf::from("binaries/ffmpeg.exe")`) che funziona solo dalla working directory del processo — non in produzione e non affidabile in development.

**Soluzione — architettura Tauri sidecar corretta**:

#### `build.rs`

```rust
println!("cargo:rustc-env=TARGET={}", std::env::var("TARGET").unwrap());
tauri_build::build()
```

Espone il target triple (es. `x86_64-pc-windows-msvc`) come costante compile-time accessibile via `env!("TARGET")` nel codice Rust.

#### `ffmpeg.rs` e `fpcalc.rs`

```rust
const TARGET: &str = env!("TARGET");

fn bundled_path(resource_dir: &PathBuf) -> PathBuf {
    let name = if cfg!(windows) {
        format!("ffmpeg-{}.exe", TARGET)
    } else {
        format!("ffmpeg-{}", TARGET)
    };
    resource_dir.join(name)
}

pub fn detect_ffmpeg(app: &tauri::AppHandle) -> FfmpegInfo {
    // 1. Sidecar bundled
    if let Ok(resource_dir) = app.path().resource_dir() {
        let bundled = bundled_path(&resource_dir);
        if bundled.exists() { ... }
    }
    // 2. system PATH
    // 3. common paths per OS
}
```

`detect_ffmpeg` e `detect_fpcalc` ora ricevono `&tauri::AppHandle` per poter risolvere la resource dir.

I comandi Tauri `detect_ffmpeg_cmd` e `detect_fpcalc_cmd` ricevono `AppHandle` automaticamente tramite l'injection di Tauri — nessuna modifica frontend necessaria.

#### Naming convention binari (`tauri.conf.json`)

```json
"externalBin": ["binaries/ffmpeg", "binaries/fpcalc"]
```

I file devono essere:
```
src-tauri/binaries/
├── ffmpeg-x86_64-pc-windows-msvc.exe   ← Windows 64bit
├── fpcalc-x86_64-pc-windows-msvc.exe  ← Windows 64bit
├── ffmpeg-aarch64-apple-darwin         ← macOS Apple Silicon
├── ffmpeg-x86_64-apple-darwin          ← macOS Intel
└── ...
```

**Stato attuale**: i file `.exe` in `src-tauri/binaries/` sono **placeholder vuoti** (0 byte) — creati come stub. `probe_ffmpeg()` li prova e fallisce silenziosamente, quindi il rilevamento scala ai fallback (system PATH, common paths). Non causa errori.

**Per attivare il bundling**: sostituire i placeholder con i veri binari FFmpeg e fpcalc rinominati secondo la convenzione Tauri. Da scaricare da:
- FFmpeg: https://www.gyan.dev/ffmpeg/builds/ (build `ffmpeg-release-essentials`)
- fpcalc/Chromaprint: https://acoustid.org/chromaprint (release binary)
