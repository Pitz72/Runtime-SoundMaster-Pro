## Contesto — la feature che non c'era

Dall'audit: **nessun modulo ha mai popolato `artist`, `title`, `album`, `genre`, `year`, `bitrate`, `sample_rate`** nel DB. Lo scanner scriveva solo path/filename/format/size. Conseguenze a cascata:

- La **fase "metadata"** della detection duplicati era di fatto morta: `metadata_key` restituiva `None` per tutti (tag NULL) — il badge "Metadata: always active" in UI era una promessa vuota.
- Il **best-pick** decideva quasi solo su formato+dimensione: bitrate e durata erano sempre NULL (salvo la durata da fpcalc della fase acustica).
- La **UI dei gruppi duplicati** mostrava "—" per artista/titolo/bitrate/durata.

## Fix — estrazione tag con lofty

Aggiunta la crate **lofty 0.24** (parser di tag nativo Rust — nessun subprocess, nessun flash di console, ~ms per file). Durante il pass di indicizzazione lo scanner ora estrae: artist, title, album, genre, year, bitrate (kbps), sample_rate, duration.

**Prestazioni — lettura selettiva**: i tag vengono letti solo per i file *nuovi*, *modificati* (size diversa) o *mai taggati* (artist NULL — record pre-v0.5.17). I rescan su librerie già taggate restano veloci come prima. Alla prima scansione post-aggiornamento tutta la libreria viene taggata una tantum.

**Transazione unica**: l'intero pass di indicizzazione (upsert + tag update) gira in una transazione — 36k commit WAL autocommit sarebbero stati un collo di bottiglia. La scansione è ri-eseguibile, quindi la perdita del batch in caso di crash è accettabile.

**Dettagli di robustezza**:
- Stringhe vuote nei tag normalizzate a NULL — la fase metadata non raggrupperà mai file con tag vuoti tra loro.
- `duration_secs` aggiornata con COALESCE: non sovrascrive con NULL una durata già calcolata da fpcalc.
- Anno estratto da `ItemKey::Year` con parsing delle prime 4 cifre (gestisce date complete tipo "2021-05-01") e range di sanità 1000–9999.
- File illeggibili da lofty → skip silenzioso e conteggio nel log; la detection dei corrotti resta responsabilità di FFprobe nel Cleaner.

**Verifica su file reali**: smoke test (`cargo test read_tags_smoke -- --ignored`) sui FLAC della libreria Genesis:

```
"A Winter's Tale - Bonus Track - Genesis_1.flac" → artist=Some("Genesis") bitrate=Some(722) dur=Some(211.64)
"Abacab - 2007 Remaster - Genesis_1.flac"        → artist=Some("Genesis") bitrate=Some(966) dur=Some(418.146)
```

## Effetti a valle (nessuna modifica necessaria, ora funzionano davvero)

- Fase metadata dei duplicati attiva sulla prossima scansione.
- Best-pick con bitrate e durata reali (formato > bitrate > durata > size).
- UI gruppi duplicati con artista/titolo/bitrate/durata visibili.
- FTS5 (trigger v0.5.15) ora indicizza contenuto reale — pronta per The Librarian.

> **Nota per il primo test**: serve un rescan del workspace per popolare i tag dei file già indicizzati.
