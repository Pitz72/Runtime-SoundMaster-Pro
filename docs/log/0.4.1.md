## Bug risolti

### BUG-1 — App si apre con la viewport in fondo alla pagina

**Sintomo**: all'avvio dell'app (e al cambio di modulo), la schermata mostrava il fondo del contenuto invece dell'inizio. Visibile in tutte le schermate.

**Causa radice — duplice**:

#### Causa A: `scrollIntoView` in `LogPanel.tsx` senza `block: 'nearest'`

File: `src/components/layout/LogPanel.tsx`

Il componente usava:
```tsx
bottomRef.current?.scrollIntoView({ behavior: 'smooth' });
```

`scrollIntoView` senza l'opzione `block` usa il default `block: 'start'`, che istruisce il browser a fare in modo che l'elemento target sia **visibile nel suo antenato scrollabile più vicino**, propagando lo scroll su tutta la catena DOM se necessario. Poiché `<LogPanel>` è posizionato in fondo al `<main>` (il container scrollabile principale), ogni chiamata a `addLog()` durante l'init faceva scorrere `<main>` fino in fondo.

**Fix**:
```tsx
bottomRef.current?.scrollIntoView({ behavior: 'smooth', block: 'nearest' });
```

`block: 'nearest'` limita la propagazione: se l'elemento è già visibile nel suo container, non fa nulla. Se è fuori vista (scroll interno del log panel), lo porta in vista nel container più interno — ma non propagha oltre.

#### Causa B: nessun reset dello scroll al cambio modulo

File: `src/components/layout/MainLayout.tsx`

Quando l'utente navigava da un modulo all'altro, la posizione di scroll di `<main>` persisteva. Se si era scorsi a metà del Cleaner e si tornava all'Hub, l'Hub appariva già scrollato.

**Fix**: aggiunto `useRef<HTMLElement>` sul `<main>` e `useEffect` che esegue `scrollTo({ top: 0 })` ad ogni cambio di `currentModule`:

```tsx
const mainRef = useRef<HTMLElement>(null);

useEffect(() => {
  mainRef.current?.scrollTo({ top: 0 });
}, [currentModule]);

// ...
<main ref={mainRef} ...>
```

### BUG-2 — rust-analyzer mostra errori `emit` non risolti in `cleaner.rs`

**Sintomo**: VS Code mostrava 3 errori "no method named `emit` found" su `cleaner.rs` righe 215, 231, 295.

**Causa**: errori di cache di rust-analyzer — il fix (`use tauri::{Emitter, Manager};`) era già stato applicato nella sessione di sviluppo v0.4.0, ma l'estensione VS Code non aveva ricaricato il file. `cargo check` passava già senza errori.

**Fix**: nessuna modifica al codice necessaria. La riga `use tauri::{Emitter, Manager};` era già presente a `cleaner.rs:16`. Il cache di rust-analyzer si aggiorna al riavvio di VS Code o al prossimo `cargo check` dal terminale.

**Documentato per riferimento futuro**: quando rust-analyzer mostra errori che `cargo check` non riporta, eseguire `cargo check` dal terminale è il test definitivo. L'estensione VS Code può avere cache obsoleta su file modificati fuori dalla sua sessione.
