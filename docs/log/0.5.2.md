## Fix — `bundled_path` cercava nel path sbagliato

**Problema in v0.5.1**: `bundled_path()` costruiva il path come `resource_dir.join(name)`, ma in dev mode `resource_dir()` di Tauri punta a `src-tauri/` — quindi cercava `src-tauri/ffmpeg-x86_64-pc-windows-msvc.exe` che non esiste. I binari sono in `src-tauri/binaries/`.

**Fix**: `bundled_path()` ora restituisce `Option<PathBuf>` e cerca in due posizioni nell'ordine:

```rust
fn bundled_path(resource_dir: &PathBuf) -> Option<PathBuf> {
    let name = "ffmpeg-x86_64-pc-windows-msvc.exe"; // (derivato da TARGET)

    // 1. Dev mode: <resource_dir>/binaries/<name>
    //    → src-tauri/binaries/ffmpeg-x86_64-pc-windows-msvc.exe  ✅
    let dev_path = resource_dir.join("binaries").join(&name);
    if dev_path.exists() { return Some(dev_path); }

    // 2. Produzione: <resource_dir>/<name>
    //    → <install_dir>/ffmpeg-x86_64-pc-windows-msvc.exe  ✅
    let prod_path = resource_dir.join(&name);
    if prod_path.exists() { return Some(prod_path); }

    None
}
```

Lo stesso fix è applicato sia a `ffmpeg.rs` che a `fpcalc.rs`.

## Effetto atteso all'avvio dell'app

Con i binari presenti e il fix applicato, il Mission Log mostrerà:

```
[SYNC]  System loaded — OK — C:\...\library.db
[SYNC]  FFmpeg [bundled]  ffmpeg version 8.1-essentials_build...
[SYNC]  fpcalc [bundled]  fpcalc version 1.6.0 (FFmpeg Lavc62.11.100...)
```

Invece dei precedenti `[ERRO] FFmpeg not detected` e `[WARN] fpcalc not detected`.

Il badge FFmpeg nella TopBar diventerà verde (ACTIVE). La detection non-conform nel Cleaner eseguirà i check video stream e corrupt oltre ai pattern YouTube.

## Priorità di rilevamento — ordine completo

```
1. Bundled (src-tauri/binaries/ in dev, resource_dir/ in prod)   ← ora funzionante
2. System PATH (ffmpeg.exe / fpcalc.exe nel PATH di sistema)
3. Common paths Windows (Program Files, WinGet, ecc.)
4. Common paths macOS (Homebrew, MacPorts)
5. Common paths Linux (/usr/bin, /usr/local/bin)
```
