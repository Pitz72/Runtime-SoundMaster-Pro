## Contesto

L'app è compilata con `windows_subsystem = "windows"` (main.rs): in build release il processo principale non ha una console. Su Windows, quando un processo GUI senza console lancia un processo figlio console (ffprobe, fpcalc, `where`), il sistema **crea una nuova finestra console visibile** per la durata dell'esecuzione del figlio.

`detect_non_conform` lancia ffprobe **una volta per file**, e la fase acoustic lancia fpcalc **una volta per file**: su una libreria da 36.000 track significa 36.000 flash di finestre console in sequenza, con furto di focus continuo.

**Perché non era mai emerso nei test**: in dev (`tauri dev` lanciato da terminale) il processo ha una console che i figli ereditano — nessuna finestra nuova. Il bug si manifesta solo nella build release installata.

## Fix — helper `hidden_command`

Nuovo helper in `utils.rs`, unico punto di spawn per tutti i processi figli:

```rust
pub fn hidden_command<S: AsRef<std::ffi::OsStr>>(program: S) -> std::process::Command {
    let mut cmd = std::process::Command::new(program);
    #[cfg(target_os = "windows")]
    {
        use std::os::windows::process::CommandExt;
        const CREATE_NO_WINDOW: u32 = 0x0800_0000;
        cmd.creation_flags(CREATE_NO_WINDOW);
    }
    cmd
}
```

`CREATE_NO_WINDOW` (0x08000000) sopprime la console del processo figlio. Su macOS/Linux l'helper è un pass-through senza effetti. Il flag non interferisce con la cattura di stdout/stderr via `.output()`.

Sostituiti **tutti** i call site `Command::new` del progetto (verificato con grep — l'unico rimasto è dentro l'helper stesso):

| Call site | Frequenza |
| --- | --- |
| `cleaner.rs` → ffprobe per-file (probe_file) | 1× per file analizzato — **il caso critico** |
| `duplicates.rs` → fpcalc per-file (run_fpcalc) | 1× per file nella fase acoustic — **il caso critico** |
| `ffmpeg.rs` → probe `-version` + `where`/`which` | al boot |
| `ffprobe.rs` → probe `-version` + `where`/`which` | al boot |
| `fpcalc.rs` → probe `-version` + `where`/`which` | al boot |
