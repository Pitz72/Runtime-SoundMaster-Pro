## Algoritmi implementati

### SHA-256 Binary Hash (Phase 1)

- Pre-filtro per dimensione file (dal DB — O(1) senza aprire file)
- SHA-256 completo solo su file con stessa dimensione → evita hash inutili
- Lettura a chunk 64KB per file grandi
- Match: identici al 100%, score 100

### Metadata Fuzzy Matching (Phase 2)

Normalizzazione `normalize_text()`:
```
"Artista & Titolo (Radio Edit)" 
→ lowercase → "artista and titolo radio edit"
→ strip non-alphanumeric → join whitespace
```
- `&` e `+` → `and`
- Rimuove parentesi, punteggiatura, simboli
- Confronto: `artist_normalized || title_normalized` come chiave di raggruppamento
- Solo track NON già raggrupati dalla fase hash
- Score: 80

### Acoustic Fingerprinting (Phase 3 — opzionale)

- Richiede `fpcalc` (Chromaprint) installato nel sistema
- `fpcalc -plain <file>` → output `FINGERPRINT=<base64>\nDURATION=<secs>`
- Fingerprint salvato nel DB (`tracks.fingerprint`) per uso futuro
- Confronto: primi 120 caratteri del fingerprint come chiave (identical tracks hanno prefisso identico)
- Skip automatico se fpcalc non disponibile — UI mostra badge "N/A"
- Score: 90

### Best-Pick Algorithm

Da PIANIFICAZIONE.md — `pick_best()`:

| Priorità | Criterio | Soglia |
|---|---|---|
| 1 | Formato: lossless (flac, wav) > lossy (mp3, aac, ogg) | — |
| 2 | Bitrate superiore | diff > 32 kbps |
| 3 | Durata maggiore | diff > 5 secondi |
| 4 | Dimensione maggiore | tiebreaker |

Override manuale disponibile nella UI per ogni gruppo.

### `src-tauri/src/duplicates.rs` *(nuovo)*

Strutture pubbliche:
- `DuplicateFile`: un file in un gruppo, con tutti i campi per best-pick + flag `is_best_pick`
- `DuplicateGroup`: gruppo di 2+ file con `match_type`, `score`, `files`, `best_pick_id`
- `DuplicateProgress`: evento `"duplicate-progress"` con `phase`, `processed`, `total`, `groups_found`
- `DuplicateDetectResult`: ritorno di `detect_duplicates`
- `DuplicateResolveResult`: ritorno di `resolve_duplicates`

Funzioni private:
- `format_score()`: lossless=3, lossy=1, unknown=0
- `pick_best()`: algoritmo multi-criterio su slice di TrackRow
- `to_duplicate_files()`: converte Vec<TrackRow> in Vec<DuplicateFile> con is_best_pick
- `normalize_text()`: lowercase + strip non-alphanumeric + deduplicate spaces
- `metadata_key()`: restituisce `"artist_normalized||title_normalized"` o `None`
- `sha256_file()`: hash SHA-256 a chunk su file aperto
- `run_fpcalc()`: spawn fpcalc, parse output plain, ritorna `(fingerprint, duration)`
- `collision_safe_path()`: identica a cleaner.rs (non condivisa per non creare dipendenze tra moduli)

Comandi Tauri:
- `detect_duplicates(fpcalc_path: Option<String>)` → async + spawn_blocking
- `resolve_duplicates(workspace_path, resolutions: Vec<(i64, Vec<i64>)>)` → async + spawn_blocking

## Il Cleaner è ora testabile

Con v0.5.0, **The Cleaner è il primo modulo completamente operativo**. Per testarlo su una libreria reale:

1. Aprire l'app (`npm run tauri dev`)
2. Hub → selezionare una cartella workspace con file audio
3. Attendere completamento scansione (indexing in SQLite)
4. Navigare su The Cleaner
5. **NON-CONFORM**: Start Analysis → revisiona → Quarantine
6. **DUPLICATES**: Start Duplicate Scan → revisiona gruppi → override best-pick se necessario → Execute Resolve
7. Verificare che i file siano effettivamente in `_NonConform/` e `_Duplicates/` nella workspace
8. Verificare che i contatori Hub si aggiornino

**Nota fpcalc**: se non installato, la fase acoustic viene saltata automaticamente. Il rilevamento via SHA-256 + metadata è sempre attivo e non richiede dipendenze esterne.
